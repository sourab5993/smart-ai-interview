# SMART INTERVIEW — Build Plan

## Product outcome

Deliver a real, responsive SMART INTERVIEW product for students and job seekers across technical, business, healthcare, law, arts, education, agriculture, vocational and other/custom courses. Course, specialization, role and practice evidence—not an IT-only template—shape interview questions, evaluation dimensions, skill gaps and study plans. The main journey is profile → optional private resume/JD analysis → course-aware interview (voice when supported or text) → Gemini answer feedback and report → readiness and skill analytics → focused plan → repeat and compare. Keep feedback educational, respectful and privacy-protective; do not fabricate ML metrics or promise employment outcomes. Remove the standalone Career Path and Notifications pages while retaining the topbar notification popover. Per the user's explicit override, keep Project Insights accessible at `/project-insights` as required by outcome 12.

## Approved architecture and material constraints

- **Authentication and data:** Supabase Auth and Supabase PostgreSQL, as expressly chosen by the user. Browser Supabase client uses the project URL and publishable/anon key; protected client requests carry the signed-in user's access token. The Express/tRPC backend validates the bearer token against Supabase Auth and resolves the role from the RLS-protected profile. Application data is accessed with the user's Supabase token through PostgREST so database RLS applies; no service-role key is used. Owner-scoped rows enforce `owner_id = auth.uid()`; learner profiles also store explicit interest areas for career ranking; catalog reads are public and catalog writes/admin reports require a database-backed admin role.
- **Database setup:** Commit repeatable, additive PostgreSQL migrations under `supabase/migrations/`; `scripts/migrate-supabase.ts` applies them through `pg` using private `SUPABASE_DB_URL`. Supabase PostgreSQL is the sole application-data store. The application does not use `DATABASE_URL` or managed MySQL. Migrations define normalized profiles/catalogs/interviews/evaluations/resumes/matches/metrics/skill-gaps/plans/bookmarks/notifications/ML signals with keys, constraints, indexes, timestamps and RLS. Private resumes use a non-public Supabase Storage bucket and user-token RLS policies; the database stores the owner and durable object key.
- **Frontend/backend:** Use React 19, TypeScript, Vite, Tailwind, Express and tRPC. `server/_core/` owns startup/auth context and validated configurable 2MB JSON/64KB form body limits (bounded between 16KB and 5MB). `server/routers.ts` validates/rate-limits protected calls; `server/ai.ts` owns server-side Gemini request schemas, prompt safety, parsing and validation, surfacing retryable service errors rather than substituting heuristic or sample scores. Gemini requests go directly to Google's API from the server using `GEMINI_API_KEY`. `supabase/migrations/` owns PostgreSQL schema/policies/seed data; `supabase/bootstrap-admin.sql` documents first-admin promotion; `scripts/migrate-supabase.ts` owns one-time additive migration execution.
- **AI, uploads and readiness:** Use the live platform-managed `gemini-3-flash-preview` model for answer evaluation, interview summaries, resume analysis, explanations, study plans and question generation. Keep calls server-only, schema-validated, concise and fast; do not silently show a transparent baseline when Gemini fails—surface a retryable error instead. Browser speech recognition is optional with editable text fallback. PDF/DOCX text is extracted with browser parsing libraries; users explicitly start analysis, and resume bytes/text plus analyses remain account-owned. Readiness remains a transparent historical preparation signal, not a trained model or hiring probability.

## Data flow

1. Supabase Auth verifies the candidate and creates/refreshes a signed access token.
2. Supabase/PostgREST applies RLS to every browser data/storage request; the tRPC AI endpoints validate the same user token before handling a request.
3. User-selected course, specialization, role, skill profile, optional resume/JD evidence and prior performance guide generated questions.
4. Each answer is evaluated with strict schema validation, then stored with per-answer dimensions and owner attribution.
5. Saved reports, session history, course/role skill gaps and transparent readiness features feed repeatable, personalized study plans and comparisons.
6. Admin pages use narrowly scoped aggregate RPCs and editable catalogs; they do not expose other learners' answers/resume text.

## Design direction

- **Design movement:** original “nocturne instrument panel”—a premium dark AI workspace mixing editorial career-coaching warmth with precise developer-tool instrumentation; no copying of reference sites.
- **Core principles:** confident legibility; course-aware personalization; purposeful depth; progressive disclosure over dashboard clutter.
- **Color philosophy:** near-black/deep-navy surfaces establish focus and trust; electric cyan signals actionable readiness; violet/indigo mark AI processing and insight; magenta is rare emphasis. Maintain contrast and avoid gratuitous gradients.
- **Layout paradigm:** asymmetric landing-page hero with an orbit/orb balancing concise copy; transition into a compact left-rail workspace and broad analytical canvas; mobile becomes a focused bottom-navigation flow.
- **Signature elements:** a restrained neural-orbit mark; fine constellation lines linking evidence to insight; slim illuminated score arcs and course-aware skill tracks.
- **Interaction philosophy:** every action gives clear state and a next step; interview controls remain immediate; errors preserve work; feedback is specific and respectful.
- **Animation:** short easing on hover/selection/progress, quiet orb breathing/listening/thinking states and desktop-only depth; CSS-light mobile treatment; respect `prefers-reduced-motion`.
- **Typography:** Inter or equivalent for interface, with a contrasting editorial display face for large landing statements; tabular score numerals; clear heading/body/label hierarchy.
- **Brand essence:** a course-aware AI coach that turns practice into evidence-led preparation for every career; **clear, encouraging, rigorous**.
- **Brand voice:** direct, constructive and evidence-led. Examples: “Practice the questions your path actually asks.” “One focused answer is progress you can measure.”
- **Wordmark & logo:** custom compact monogram formed by conversation brackets around an ascending signal/orbit, paired with a tracked SMART INTERVIEW wordmark.
- **Signature brand color:** electric cyan.

## Behavioral Interview Analysis mode

- **Product boundary:** Add a separate speech-only coaching mode without changing the existing written-answer interview. The mode reuses real historical questions selected by the signed-in user, records explicit camera/microphone consent and device readiness, and keeps all results owner-scoped. It reports observable presentation signals and measurement reliability, never facial identity, emotion, deception, personality, disability, employability, or a hiring verdict.
- **Client module:** Add `client/src/features/behavioral-interview/` with a launcher/configuration page, historical-question selector, device setup and consent, a speech-only room, a Web Worker inference pipeline, telemetry aggregation, and a report view. Use `@mediapipe/tasks-vision` with the official Face Landmarker, Pose Landmarker Lite, and Hand Landmarker `.task` assets, initialized once per session and disposed at completion. Face Landmarker uses `numFaces: 2`, transformation matrices and blendshapes; gaze remains approximate and camera-relative. Pose and hand coverage gaps become unavailable data, not zero scores.
- **Runtime and privacy:** Capture camera and microphone only after the user starts setup and grants permission. Run visual inference locally in a worker at an adaptive sampling rate; send no webcam frames to the backend. Record audio only for the current speech answer, use the existing authenticated transcription service, store transcript text only when consented, and never store raw video/audio by default. Model asset URLs and versions are documented in `models/behavioral/README.md`.
- **Backend/data:** Add additive Supabase migrations for behavioral sessions, selected source questions, spoken answers, timestamped observations, per-question reliability/category summaries, session summaries, and optional report linkage. Add owner-checked protected procedures for question eligibility, session creation, answer metadata, observations, completion and report retrieval. Validate all question/session ownership server-side and calculate persisted scores from valid observations with denominator renormalization.
- **Scoring/reporting:** Keep original answer-quality scores unchanged. Calculate configurable Behavioral Coaching Score categories from valid eye-gaze, head movement, gesture/upper-body, camera presence and speech-delivery observations; exclude unavailable categories and show coverage/reliability. If valid coverage is insufficient, say so instead of manufacturing a score. If both components are available, show a clearly labeled optional combined practice score using 80% answer quality + 20% Behavioral Coaching Score, never as a hiring prediction.
- **Speech:** Use real `MediaRecorder` audio and the existing server transcription path; preserve question IDs, timestamps, durations and retry state. No typed-answer controls appear in the new mode, while the original interview keeps its existing text and optional browser speech flow.

## Remaining Live Interview completion scope

- Keep Live Interview distinct from both Simple Interview and Behavioral Interview Analysis. Show a reusable, animated virtual-interviewer character that changes visual state with the actual speaking/listening/processing phase. Use browser speech recognition for real-time partial transcripts where supported and retain an honest retryable fallback for providers that only accept a completed audio blob; never label the fallback as streaming.
- Offer camera framing observations only as a separately explained, explicit opt-in. Request a video-only stream after consent, run Face/Pose/Hand Landmarker inference locally in a disposable Web Worker, and send no image, frame, landmark coordinate or inferred psychological state to the server. Persist only optional, bounded aggregate visibility counts and usable-sample metadata. Do not score gaze, expression, confidence, honesty, competence, personality, health, protected traits, or hiring suitability. Unsupported devices and insufficient samples produce an unavailable/limited message, never a zero score.
- Expand answer coaching with role- and question-linked relevance, evidence/correctness, completeness and reasoning dimensions. Report answer-quality scores separately from transcript-derived communication observations and any optional user-requested framing counts. Require evidence-grounded notes; do not infer accent or personal traits, fabricate transcript/scoring data, or present a coaching estimate as objective model accuracy or a hiring decision.
- Store behavioral answers and their bounded observation replacement through an authenticated Supabase RPC that locks the owner-scoped parent session, validates the complete five-category record, and derives the camera sample threshold from saved frame metadata (at least 8 reliable visible-face samples spanning 3.5 seconds). Recompute per-answer and session category scores in PostgreSQL using the same defined category weights; never accept client-supplied aggregate scores as authoritative. Complete the session only after every question has a saved answer, preserve linked original evaluations, calculate the optional combined score only from both available components, and atomically store the report with the terminal state.

## Managed background work

- Add additive Supabase tables for schedule-to-business-task registration, idempotent run ledger, refresh metadata and leased per-session finalization. Register published application callbacks under `/api/scheduled/` only after their handler is live. The handler verifies the HS256 `app_session_id` ticket, expiry and project claim; resolves the identity with `GetUserInfoWithJwt`; looks up its own registered task by the returned `taskUid`; and never treats untrusted callback-body identifiers as authorization.
- Schedule a daily UTC Gemini question-bank refresh at 02:30 UTC (`0 30 2 * * *`) that validates a bounded structured batch, balances course categories and difficulty, rejects exact/near duplicates, preserves the last successful bank on failure, records start/success/failure, model/time/count/error, and prevents overlapping duplicate runs. Provide a separately authenticated admin-only manual trigger.
- Run the recurring deadline worker every 60 seconds (`0 * * * * *`) to finalize due Simple and Live sessions without an open browser tab. It processes only server-clock-expired, owner-scoped sessions, evaluates actual persisted accepted answers/transcripts, skips already-evaluated content, persists reports idempotently, rejects late answers, and uses expiring per-session claims so retries cannot duplicate a score or report.
- Use the same owner-checked UUID claim from browser and scheduled completion paths. Fence every worker write by the current unexpired token, compare-and-set session state, reject late answer/evaluation/transcript/question/camera-summary writes inside PostgreSQL, and commit each report with its terminal session status atomically. A stale caller may not overwrite or release a replacement worker's claim.
- Save Simple answers through an authenticated owner/question-scoped RPC that locks the parent session and validates its authoritative database status and deadline. Keep legacy PostgREST writes safe with the same lock/deadline/claim checks in the answer trigger, and serialize browser/worker claim, release and persistence paths in one session-before-lease lock order. Require both the locked-row read and final update for Live camera summaries to remain before `deadline_at`.
